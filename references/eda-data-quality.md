# EDA 与数据质量体检

**第一步该做什么**：产出一份"数据质量报告"（缺失/分布/泄漏红旗/格式问题），报告完成前不改任何数据。EDA 是只读阶段。

## EDA 最小清单

1. 形状、dtypes、内存；`describe()` 看量纲与极端值。
2. 缺失：比例、机制（MCAR/MAR/MNAR 猜测）、**缺失 ≠ 0**。
3. 目标变量分布：不平衡比例决定评估策略。
4. 特征与目标的相关热图；特征间共线性（|r|>0.9 标记）。
5. 时间字段：时区、间隙、重复；实体字段：基数（高基数考虑编码策略）。

## 概念区分（易错，已确认）

- **缺失** vs **ND（未检出）** vs **LOQ（低于定量限）** vs **真零**：四者编码方式不同，混用会污染分布。ND/LOQ 不能当 0 处理，需按方法定量限单独标记。
- 单位：发现两列同名不同单位（如 mg/dL 与 mmol/L）→ 先统一再分析，否则相关系数无意义。

## 数据质量闸门（data-quality-pipeline 的五道闸门）

1. 完整性：关键列非空率 ≥ 阈值。
2. 唯一性：主键无重复。
3. 有效性：值域/枚举/格式合规率。
4. 一致性：跨列/跨表逻辑（如订单金额 = 单价×数量）。
5. 时效性：数据新鲜度与更新频率。

闸门失败的处理是**报告 + 隔离**（quarantine），不是静默修复。

## 可复现性与数据工程铁律（全网对标补强，来源 ml-engineering-agent-manifesto）

- **四层 seed 铁律**：固定 random/numpy/torch/CUDA 四层 seed；CUDA 非确定性 kernel 或 DataLoader 多 worker 未 seed 时，结果 MUST 标注"不可复现"。
- **merge 校验**：`pd.merge` MUST 显式指定 how 并加 `validate`（防行爆炸）；join 后行数与预期不符即报错，禁止静默继续。
- **副本纪律**：DataFrame 子集修改前 `.copy()`；读 CSV 后检查 dtype。
- **实验可比性**：每个 run MUST 记录 params + metrics + git SHA + 数据版本（或 data hash）；缺失任一字段的 run 禁止用于横向比较。
- **入口校验**：pipeline 入口校验 schema、null 容忍度与值域；违规分"fail loudly / quarantine"二选一，禁止不校验直接训练。
- **Notebook 纪律**：假设 cell 可能乱序执行，状态禁止跨 cell 隐式传递；重复使用 >1 次的逻辑 MUST 抽为带类型标注与测试的模块；重构成"薄驱动 + 可导入函数"。

## 工具速记

- 大文件：`pyreadstat`/分块读；自动 EDA 用 ydata-profiling 但**只当草稿**，结论须人工复核。
- 缺失可视化：`missingno.matrix/bar`。
- 检测泄漏红旗直接用 `timeseries-leakage.md` 的判据表。

## 如何证明数据理解正确

① 对每个关键列能回答"它业务上是什么、怎么采集、单位是什么"——答不出即"数据不足"，先问数据提供方；② 分布异常（双峰、截断）能找到业务解释；③ 抽 5 条原始记录人工核对与 DataFrame 一致。三条做齐才允许进入建模。
